迁移到 Astro + astro-paper 方案

2026-09-30 · 从 duanyzhi.github.io 现在的 Jekyll Now 迁到 AstroPaper v6

先看结论

能迁，而且只用一个仓库就行，不用买服务器、不用换托管。

总共就三件事：把模板弄下来、把文章挪进去、让 GitHub 自动构建。前两件是体力活，第三件贴一个文件就好。

本地不装东西也能干，让 GitHub 那边的机器去装、去构建。想本地预览效果才需要装 Node。

唯一要提前知道的是个坑：构建的时候它要去 Google 抓字体，抓不到就报错。国内本地构建基本必踩。绕法在下面「踩到的坑」那节。

先说不需要什么

  • 不需要换账号、换域名，仓库还是 duanyunzhi.github.io。
  • 不需要 Cloudflare。astro-paper 文档里写 Cloudflare 是它自己 demo 用的，跟你没关系。
  • 不需要本地装 Ruby 了，也不用管 Jekyll 那套。反过来，本地要装 Node。
  • 不需要把文章重写成 HTML。正文还是 Markdown，想嵌 HTML 也随时能嵌。
  • 不需要 .nojekyll。用 Actions 发布时 Jekyll 不参与。（只有改回「按分支发布」才需要，原因见最后。）

为什么会有「下依赖」和「构建」这一步

你现在这套是 Jekyll Now。特点是：你只写 Markdown，GitHub 那边有现成的 Jekyll 帮你编译，所以你本地什么都不用装。这是 GitHub Pages 内置的功能。

Astro 不在 GitHub 内置的那几个里面。GitHub 不认 .astro 文件，它只会把编译好的 HTML、CSS、JS 发出来。

所以 Astro 得先「构建」一次：把模板和文章编译成一堆静态网页文件。构建要用到一堆别人的现成包（框架、样式、搜索、生成分享图这些），一共 565 个。所以要下依赖。

我实测过：npm install 大概 1 分钟，npm run build 几十秒到两分钟。只在第一次和改了代码的时候需要。

关键点：这一步不用你在本地做。让 GitHub Actions 在 GitHub 的机器上做，你只管 push。

只用一个仓库行不行

行。同一个仓库里干两件事：

  1. Astro 的源码（src/、public/ 这些）就放在仓库里。
  2. 仓库里多一个 .github/workflows/deploy.yml。每次 push，GitHub 自动装依赖、构建、把结果发布到 Pages。

你唯一要在网页上改的设置：仓库 Settings → Pages → Source，从「Deploy from a branch」改成「GitHub Actions」。

发布流程长这样：

你 push 源码
   ↓
GitHub Actions 跑 npm install + npm run build
   ↓
构建出来的静态文件发布到 duanyzhi.github.io

注意一件事：现在的 Jekyll 文件和 Astro 源码不能混着放。迁的时候要把 _config.yml、_layouts、_posts、style.scss、index.html 这些都删掉，换成 Astro 的目录结构。想稳一点就先开个分支试。

动手步骤

第 1 步 把模板弄下来

三种都行，挑一种。

# 方式一：官方脚手架（会问你几个问题，一路回车也行）
npm create astro@latest -- --template satnaing/astro-paper

# 方式二：直接克隆
git clone https://github.com/satnaing/astro-paper.git

# 方式三：下压缩包（网络不好时最稳）
curl -L -o ap.tar.gz https://codeload.github.com/satnaing/astro-paper/tar.gz/refs/heads/main
tar xzf ap.tar.gz

然后把里面的东西挪进你的 duanyunzhi.github.io 仓库。想本地预览就再跑 npm install 和 npm run dev，浏览器开 localhost:4321。

版本情况：模板是 astro-paper v6.1.0，要求 Node 22.12 以上。你机器上是 v22.23.1，够用。

第 2 步 改站点配置

只改一个文件：astro-paper.config.ts。要改的就是这些。

字段填什么
site.urlhttps://duanyzhi.github.io/
site.title你的站点名
site.description一句话简介
site.author你的名字，文章的 author 默认取这个
site.profile你的主页或头像链接
site.lang / site.timezone中文站填 zh-CN，时区 Asia/Shanghai
posts.perPage / perIndex列表每页几篇，默认 4
features.dynamicOgImage自动生成分享图，建议先设 false（原因见坑一）
features.searchpagefind，站内搜索，默认开着
socialsGitHub、邮箱这些链接

顺手把 public/default-og.jpg 换成你自己的封面图，不然别人分享你文章时看到的是 AstroPaper 的图。

第 3 步 文章挪窝

老位置是 _posts/，新位置是 src/content/posts/。可以建子目录分类，子目录名会进网址。目录名以 _ 开头就不进网址，只当分类用。

你现在有 29 个 md，其中 23 个有 title。搬过去每个都要补字段，见下一节。

文件名建议顺手改干净。新版的网址是照文件名来的，跟日期没关系了，日期从 pubDatetime 读。所以 2017-11-10-CNN.md 可以改成 cnn.md，网址就是 /posts/cnn/，比原来带日期好看。

第 4 步 图片挪窝

把 images/ 整个拷到 public/images/。文章里全改成站内绝对路径：

<!-- 原来这样，外链，会挂 -->
![resnet](https://raw.githubusercontent.com/duanyzhi/.../images/ResNet.png)

<!-- 改成这样，图在仓库里，稳 -->
![resnet](/images/ResNet.png)

想加图注、控制大小，就这么写（Markdown 里直接嵌 HTML）：

<figure>
  <img src="/images/cnn.PNG" alt="CNN 结构" width="600">
  <figcaption>CNN 结构</figcaption>
</figure>

说清楚一个区别：放 public/ 的图 Astro 不加工，原图多大就多大；想让它自动压缩、转格式，得放 src/assets/ 并在文章里用相对路径引。你手上 19 张图加起来 6.2MB，先扔 public/ 最省事，嫌慢再压缩。

第 5 步 加部署文件

新建 .github/workflows/deploy.yml，内容照抄：

name: Deploy to GitHub Pages

on:
  push:
    branches: [master]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: withastro/action@v6

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5

两个地方看你的情况改：branches 里你的主分支叫什么就写什么，你现在是 master，很多人是 main。withastro/action 默认用 Node 24、默认跑 npm run build，都不用填。

第 6 步 开 Pages 的 Actions 发布

仓库 Settings → Pages，Source 选 GitHub Actions。改完 push 一次，去 Actions 页面能看到跑起来了。第一次大概两三分钟。

第 7 步 收拾旧摊子

确认新站能开、文章都在，再删旧的：_config.yml、_layouts/、_includes/、_sass/、_posts/、style.scss、index.html、404.md、blog.md、about.md、paper.md。

内容别丢：about.md 改成 src/content/pages/about.md，格式是新的一套（只要 title 必填）。你 blog.md 里那两个外链（CSDN、知乎），挪到 astro-paper.config.ts 的 socials 里更合适。

文章要补哪些字段

新版每个文章开头必须有三样：title、description、pubDatetime。少一个就构建报错。你现在老文章只有 title，等于 23 篇都要补。

字段要不要填说明
title必填标题
description必填摘要，用在列表和搜索结果里，也管搜索排名
pubDatetime必填发布时间，ISO 格式，比如 2017-11-10T00:00:00Z
tags可选不填就归到 others 这个标签
author可选不填取站点配置里的作者
modDatetime可选改过才填
featured可选设为 true 就上首页推荐位
draft可选草稿，true 就不发布
ogImage可选分享图，不填用默认图
canonicalURL可选同一篇在别处也发过，填那边的地址
timezone可选单独给这篇指定时区

前后对比，拿你那篇 CNN 举例。

现在是这样：

---
layout: post
title: Convolutional Neural Networks
---

改成这样（文件放 src/content/posts/cnn.md，网址就是 /posts/cnn/）：

---
title: Convolutional Neural Networks
description: CNN 基础笔记，卷积、池化、神经元模型都在这里。
pubDatetime: 2017-11-10T00:00:00Z
tags:
  - 深度学习
  - CNN
---

layout: post 这行直接删掉，新版不认这个，是自动套的。

还有个变化得知道：老站网址是 /CNN/ 这种，新站是 /posts/cnn/。网址全变了，外面有链接进来会 404。要保老链接得写跳转，这事可以做，但不用一开始就做。

实测踩到的坑

坑一 构建要联网抓 Google 字体，抓不到就失败。

我在本地真跑了一次构建，报错是这样：

[WARN] [assets] No data found for font family Google Sans Code
[ERROR] Error: Cannot find the font path.
[ERROR] [build] Caught error rendering /og.png

原因：模板的字体用的是 Google 的「Google Sans Code」，构建时要去 Google 下载。这台机器连不上，字体就没有，分享图的生成就崩了，整个构建失败。

我在国内，本地构建基本必踩这个。我在你这台机器上实测的情况是：curl 能连上 fonts.googleapis.com，但 Node 的网络层连不上，一直超时。

三个绕法，按推荐顺序：

  1. 不本地构建，丢给 GitHub Actions 跑。GitHub 的机器在海外，能连 Google，这事就没了。
  2. 把字体换成本地的（字体文件放仓库里），适合必须本地构建的情况。
  3. 把生成分享图的代码删掉或改掉。

提醒一句：光在配置里把 dynamicOgImage 关成 false 不够。我试了，站点还有一个固定的 /og.png 也要这个字体，照样报错。

坑二 公式要自己装插件。模板默认不带 LaTeX。要显示 $$ 公式得额外装 remark-math、rehype-katex、katex 三个包，再改 astro.config.ts。你 29 篇里只有一篇（排序算法那篇）用了公式，不急可以先不管。

坑三 老站的文件名规则和新的不一样。老站文件名是 年-月-日-标题.md，新站不认这个格式，纯粹拿文件名当网址用。日期得在 pubDatetime 里写。

坑四 老文章外链图会挂。你自己仓库里就有 4 处 imgur、3 处 raw.githubusercontent、2 处 cloudfront。这几个我实测：imgur 连不上，cloudfront 那俩域名已经没了，raw 那条反复超时。迁的时候顺手全换成 /images/...，不然白迁。

坑五 你的 CNAME 是空的。现在没绑自己的域名，站点就是 duanyzhi.github.io。迁完还是这样，不用管。等哪天真想绑域名，再单独弄。

一页命令清单

# 1. 起项目（在空目录里）
npm create astro@latest -- --template satnaing/astro-paper

# 2. 装依赖（本地预览才需要）
npm install

# 3. 本地预览，浏览器开 localhost:4321
npm run dev

# 4. 构建，产物在 dist/
npm run build

# 5. 构建结果本地预览
npm run preview

# 6. 推上去，剩下交给 GitHub Actions
git add .
git commit -m "migrate to astro-paper"
git push

搬文章、改图片路径这两件事没有现成命令，得手工过一遍。29 篇不算多，一天能弄完。
